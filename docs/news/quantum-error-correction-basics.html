Quantum error correction basics: syndromes, thresholds and why overhead matters

By PhotonDispatch Staff · Published 31 October 2026 · Last updated 31 October 2026

Short answer: Quantum error correction protects quantum information by encoding it redundantly across many qubits, repeatedly measuring parity checks that reveal errors without revealing the data, and using a classical decoder to work out and undo the most likely errors. It only helps if the hardware's error rate is below a threshold, and it costs many physical qubits per protected qubit.

Quantum computers suffer two basic kinds of error: bit flips, which swap 0 and 1, and phase flips, which change the sign relationship in a superposition. Real noise is continuous, but measuring a code's parity checks forces it into one of a discrete set of outcomes, so correcting bit flips and phase flips is enough to handle general errors. Gottesman's introduction to the field sets out this 'discretisation of errors' and the stabilizer formalism most codes are built on.

The pattern of parity-check results is called the syndrome. In each round of error correction, helper qubits interact with groups of data qubits and are measured; a change in the syndrome flags an error nearby. A decoder, which is ordinary classical software or hardware, takes the stream of syndromes and decides which correction to apply. It has to keep pace with the machine. Google Quantum AI's 2024 Nature paper reported an average decoder latency of 63 microseconds at distance 5 with a 1.1-microsecond cycle time, running for up to a million cycles.

The threshold theorem is what makes the approach worthwhile. In the 1990s Dorit Aharonov and Michael Ben-Or, among others, showed that if each component's error probability is below some constant threshold, arbitrarily long quantum computations can be made reliable with only polylogarithmic overhead, by using codes within codes. Modern surface-code estimates put the threshold for realistic noise near 1% per operation, according to Fowler and colleagues' 2012 review.

Overhead is the catch. Fowler's review estimated that useful fault-tolerant machines would need very large numbers of physical qubits, because each logical qubit uses hundreds to thousands of them and some operations need extra resources, such as 'magic states', to complete a universal gate set. Lower physical error rates, better decoders and more efficient codes all shrink that overhead, which is why researchers track the logical error rate per cycle and how fast it falls as codes grow.

Experiments have begun to show the expected behaviour. Google reported in 2024 that its distance-7 surface-code memory on the Willow chip had an error rate of 0.143% per cycle, and that each increase of two in code distance cut the logical error rate by a factor of 2.14. The same paper noted that rare correlated error events, roughly once an hour, limited its longest repetition-code runs.

Analysis

Error correction has moved from theory to engineering, but the open questions are practical: how to handle correlated errors, how to decode fast enough at scale, and how many physical qubits a useful machine will really need. Resource estimates differ widely depending on hardware assumptions, so a single number for 'qubits needed' should be read with its assumptions attached.
